  <name>Task 1: Create question-generator.js service</name>
  <files>mcp-server/src/services/question-generator.js</files>
  <action>
Create question generation service that combines multiple sources:

**generateInterviewQuestions(jobId, options)**
Options: { categories: ['behavioral', 'technical', ...], count: 10, difficulty: 'mixed' }

Generation sources (per CONTEXT.md - balanced mix):
1. **JD Requirements** (source: 'jd-requirement')
   - Extract keywords from job notes/description
   - Generate "Tell me about your experience with {keyword}" questions
   - Tag as technical or behavioral based on keyword type

2. **Profile Gaps** (source: 'profile-gap')
   - Load job match data if available
   - Generate questions probing gap areas
   - Tag as medium/hard difficulty (gaps = weaker areas)

3. **Profile Strengths** (source: 'profile-strength')
   - Use getRelevantStories from interview-prep.js
   - Generate questions that let strengths shine
   - Tag as easy/medium difficulty

4. **Company Research** (source: 'company-research')
   - Load company research if exists
   - Generate culture-fit questions from values
   - Include questions about industry challenges

5. **Interviewer Style** (source: 'interviewer-style')
   - Load interviewer research for job
   - Generate questions matching their expectedQuestionTypes
   - Match depthExpectation to difficulty

For each question generated:
- Call linkQuestionToStories(questionText, profile, jobContext) to find relevant stories
- Add talking points from research (company highlights, shared interests)
- Assign difficulty based on source and context

**linkQuestionToStories(questionText, profile, jobContext)**
- Use getRelevantStories with keywords extracted from question
- Return top 3 stories with relevanceScore
- Format: [{ storyId, storyTitle, relevanceScore }]

**getQuestionsForJob(jobId)**
- Load from {jobId}-questions.json if exists
- Return null if not generated yet

Persist questions to {jobId}-questions.json using atomic write pattern.

Question category templates:
- behavioral: "Tell me about a time when...", "Describe a situation where..."
- technical: "How would you approach...", "Walk me through..."
- system-design: "Design a system that...", "How would you architect..."
- culture-fit: "What's your approach to...", "How do you handle..."

<task type="auto">
  <name>Task 2: Create practice-session.js service</name>
  <files>mcp-server/src/services/practice-session.js</files>
  <action>
Create practice session lifecycle service:

**createPracticeSession(jobId, options)**
Options: {
  sessionType: 'full-interview' | 'category-focus' | 'single-question',
  feedbackTiming: 'immediate' | 'batched',
  questionIds: [] (optional - defaults to all questions for job),
  categoryFilter: 'behavioral' (optional - for category-focus)
}

Returns: { sessionId, questions, feedbackTiming }

Creates session in {jobId}-practice-sessions.json:
- Load existing sessions array (or init empty)
- Create new session with PracticeSessionSchema structure
- Save with atomic write
- Return session with question objects for practice

**submitAnswer(sessionId, answer)**
Answer: { questionId, answerText, inputMethod, duration }

- Load sessions file, find session by ID
- Validate answer using PracticeAnswerSchema
- Add to session.answers array
- Save with atomic write
- Return { success: true, answersSubmitted: count }

Note: Score and feedback are NOT set here - they're set by the scorer service (Plan 03)

**completeSession(sessionId)**
- Load session, set completedAt
- Calculate summary: questionsAttempted, strongCategories, improvementAreas
- Note: averageScore calculated only if scores exist (from scorer)
- Save and return completed session

**getSessionsForJob(jobId)**
- Load {jobId}-practice-sessions.json
- Return array of session summaries: { id, sessionType, startedAt, completedAt, questionsAttempted }

**getSession(sessionId)**
- Load all sessions, find by ID
- Return full session with answers

Storage: mcp-server/data/job-research/{jobId}-practice-sessions.json
Format: { sessions: [...], lastUpdated: ISO string }

Per CONTEXT.md:
- No timer (focus on content quality)
- All sessions saved automatically
- User chooses feedback timing at session start
  </action>
