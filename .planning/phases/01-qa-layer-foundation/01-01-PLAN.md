Create schemas/job.schema.js with Zod schemas:
- JobStatusSchema: enum of valid statuses (apply-now, maybe, probably-not, applied, archived)
- ConnectionSchema: union of string (legacy) or object with name, role, linkedIn, notes, isPrimary, reachedOut
- UpdateSchema: object with date, timestamp (both optional), type, notes/text
- JobSchema: full job object with id (positive int), title, company, industry, location, salary, fitScore (0-100), status, posted, found, applied, followup, url (url validation), symbols, connections, sources, notes, updates, hiringManager
- JobsDataSchema: wrapper with jobs array, searchHistory, settings, version, lastUpdated
- validateJobsData(data, options): Returns { valid, errors, data } - advisory mode warns but returns data

Create test fixtures:
- test/fixtures/valid-job.json: Complete job entry matching real data structure
- test/fixtures/invalid-jobs.json: Array of invalid cases (missing required fields, wrong types, invalid status, fitScore out of range, malformed URL)

Create schemas/job.schema.test.js with tests:
- Valid job passes validation
- Each invalid case is caught with descriptive error
- Advisory mode returns data even on validation failure
- Strict mode throws on validation failure

  <files>
    schemas/workflow.js
    schemas/workflow.test.js
  </files>
  <action>
Create schemas/workflow.js with:
- VALID_TRANSITIONS constant: object mapping each status to array of allowed target statuses
  - apply-now: can transition to maybe, probably-not, applied, archived
  - maybe: can transition to apply-now, probably-not, applied, archived
  - probably-not: can transition to maybe, apply-now, archived
  - applied: can only transition to archived (terminal except archive)
  - archived: empty array (terminal state)
- isValidTransition(fromStatus, toStatus): Returns boolean
- getValidNextStatuses(currentStatus): Returns array of valid next statuses
- validateStatusTransition(fromStatus, toStatus): Returns { valid, error? } with descriptive error message if invalid

Create schemas/workflow.test.js with comprehensive tests:
- All valid transitions return true
- Invalid transitions return false with reason
- Self-transitions (same status) return false
- Unknown status handled gracefully (returns false, not crash)
- applied cannot revert to non-archived states
- archived is terminal (nothing allowed)
- Edge cases: null/undefined inputs
  </action>
