Create skill-gap-aggregator.js building on resume-matcher.js patterns (ANLT-03):

1. Export `aggregateSkillGaps(jobs, profile)`:
   - Import extractJobKeywords from resume-matcher.js
   - Process each job's description/notes field
   - Compare extracted skills against profile.skills
   - Count occurrences per missing skill
   - Filter to minimum 3 occurrences (per RESEARCH.md Pitfall 5)
   - Track context: which industries/roles request each skill
   - Return sorted by frequency: `[{ skill, count, industries: [], roles: [], priority }]`
   - Priority: 'high' if count >= 10, 'medium' if count >= 5, 'low' if count >= 3

2. Export `getGapTrends(jobs, profile, dateRanges)`:
   - Per CONTEXT.md: Track closed, new, and persistent gaps
   - Compare gaps across date ranges (e.g., last 30d vs previous 30d)
   - Return `{ closed: [], new: [], persistent: [], trending: { up: [], down: [] } }`
   - Closed: skills that were gaps but now in profile
   - New: skills not in previous gaps but appearing now
   - Persistent: gaps appearing in both periods
   - Trending up: count increased by >50%
   - Trending down: count decreased by >50%

3. Export `getGapRecommendations(gaps, targetRoles)`:
   - Per CONTEXT.md: Priority ranking based on frequency and impact
   - Cross-reference gaps with targetRoles from profile
   - Return `[{ skill, priority, rationale, actionType }]`
   - ActionType: 'learn' (add to skills), 'highlight' (already have, needs visibility), 'research' (prepare for questions)
   - Rationale: "Requested in 15 JDs, common for {industry} roles"

4. Handle edge cases:
   - Empty jobs array returns empty gaps
   - Jobs without description/notes are skipped
   - Profile without skills shows all extracted keywords as gaps

Create criteria-recommender.js for fit criteria evolution (ANLT-04):

1. Export `analyzeOutcomes(evolutionLog)`:
   - Import loadFitConfig from fit-config.js
   - Analyze evolutionLog entries where type === 'outcome'
   - Correlate fitScore with outcome (positive/negative/neutral)
   - Return `{ correlations: { highScorePositive, lowScoreNegative, anomalies }, sampleSize, confidence }`
   - Anomalies: jobs with high fit score but negative outcome (indicates criteria mismatch)

2. Export `generateRecommendations(jobs, config)`:
   - Per CONTEXT.md: Both outcome and pattern triggers
   - Outcome-based: If high-fit jobs consistently rejected, suggest loosening criteria
   - Pattern-based: Analyze what user actually applies to vs fit scores
   - Return `[{ type, criteria, currentValue, suggestedValue, confidence, rationale }]`
   - Types: 'add_title', 'remove_title', 'adjust_salary', 'add_industry', 'adjust_weight'
   - Per CONTEXT.md: Surface only when confidence is high enough (n >= 5)

3. Export `previewCriteriaChange(jobs, change)`:
   - Per CONTEXT.md: Preview before apply (show impact on existing job scores)
   - Simulate the criteria change against all jobs
   - Return `{ affected: number, scoreChanges: [{ jobId, title, company, oldScore, newScore, delta }], summary }`
   - Summary: "12 jobs affected: 8 score increases, 4 decreases, avg +5 points"

4. Export `applyCriteriaChange(change, reason)`:
   - Wrapper around fit-config.js updateFitCriteria
   - Log to evolutionLog with structured reason
   - Return result from updateFitCriteria

5. Confidence requirements:
   - Recommendations only generated with n >= 5 outcomes
   - Include confidence level in each recommendation
   - Per RESEARCH.md: Always show sample size
