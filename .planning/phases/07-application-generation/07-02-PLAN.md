<task type="auto">
  <name>Task 2: Create Document Review Service</name>
  <files>mcp-server/src/services/document-review.js, mcp-server/src/services/document-review.test.js</files>
  <action>
Create document review service with LanguageTool integration:

1. **checkGrammar(text, language = 'en-US'):**
   - POST to https://api.languagetool.org/v2/check with { text, language, enabledOnly: 'false' }
   - Map response.matches to issues array with type, message, context, offset, length, suggestions, severity
   - Calculate score: 100 - (5 per error, 2 per warning)
   - On API failure, return { issues: [], score: null, error: message }
   - Use native fetch (Node 18+)

2. **checkATSCompatibility(text, keywords = []):**
   - Check for ATS-unfriendly patterns:
     - Non-ASCII characters (deduction 5)
     - HTML tags (deduction 10)
     - Tab characters (deduction 3)
     - Pipe characters (deduction 2)
   - Calculate keyword coverage: (matched / total) * 100
   - If coverage < 50%, add warning issue
   - Return { score, issues, keywordCoverage }

3. **checkFactualAccuracy(text, profile):**
   - Extract dates from text using regex /\b(19|20)\d{2}\b/g
   - Compare against profile.experience dates
   - Extract company names using /(?:at|for|with)\s+([A-Z][A-Za-z\s]+)/g
   - Compare against profile.experience companies
   - Return { verified: [...], unverified: [...], conflicts: [...] }

4. **analyzeTone(text, communicationPrefs):**
   - Count formal indicators (hereby, pursuant, furthermore, etc.)
   - Count casual indicators (awesome, cool, stuff, gonna, etc.)
   - Determine detected tone: 'casual', 'formal', or 'balanced'
   - Check consistency with communicationPrefs.tone
   - Return { detected, consistent, issues }

5. **reviewDocument(documentType, content, jobDescription, profile):**
   - Extract keywords from jobDescription using extractJobKeywords from resume-matcher.js
   - Run all checks in parallel (Promise.all)
   - Calculate length: wordCount, charCount, withinLimits based on documentType limits
   - Calculate overallScore as average of component scores
   - Determine blockers: >3 grammar errors, ATS <70, any factual conflicts
   - Return DocumentReviewSchema-compliant object
   - readyToUse = blockers.length === 0 && overallScore >= 75

Tests should mock LanguageTool API calls to avoid rate limits during testing.
  </action>

Tests pass for: grammar check (mocked), ATS check, factual accuracy, tone analysis, full review
  </verify>
  <done>
reviewDocument returns comprehensive review with grammar (via LanguageTool), ATS, tone, length, and factual checks
  </done>
</task>

  <files>mcp-server/src/services/keyword-optimizer.js, mcp-server/src/services/keyword-optimizer.test.js</files>
  <action>
Create keyword optimizer service following CONTEXT.md decision: "keyword optimization, same structure preserved"

1. **reorderSkillsByRelevance(skills, targetKeywords):**
   - Handle grouped format: { "Technical": ["React", "Node"], ... }
     - For each category, sort skills with matching keywords first
   - Handle flat array format: ["React", "Node", ...]
     - Sort skills with matching keywords first
   - Return reordered skills in same format as input

2. **scoreTextRelevance(text, keywords):**
   - Count how many keywords appear in text (case-insensitive)
   - Return count

3. **analyzeKeywordCoverage(resumeData, keywords):**
   - JSON.stringify resumeData and search for each keyword
   - Return { total, matched, missing, matchedKeywords, missingKeywords, coveragePercent }

4. **optimizeResumeForJob(resumeData, jobDescription, research = null):**
   - Extract keywords using extractJobKeywords from resume-matcher.js
   - Reorder skills: put matching keywords first within each category
   - Reorder experience bullets: within each role, sort bullets by keyword relevance (most relevant first)
   - Track optimizations: array of { section, action, reason }
   - Calculate keyword coverage
   - If research provided with highlights, add researchIntegration suggestion
   - Return:
     ```
     {
       optimizedData: resumeData (modified in place),
       optimizations: [...],
       keywordCoverage: { total, matched, missing, coveragePercent },
       researchIntegration: { available, suggested } | null,
       summary: "N optimizations applied, M/T keywords covered"
     }
     ```

**Important:** This does NOT rewrite content. It only reorders existing content. Per CONTEXT.md: "same structure preserved, reorder and emphasize sections based on JD keywords. Not full rewrites per job."
