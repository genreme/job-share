Create learning extraction service following learning-queue.js patterns:

**Imports:**
```javascript

import { validateInterviewLearning, validateLearningStorage } from '../../../schemas/interview-learning.schema.js'
```

**Storage paths:**
- RESEARCH_DIR: mcp-server/data/job-research
- getLearningsPath(jobId): `{jobId}-learnings.json`

**Functions to implement:**

1. `queueInterviewLearning(learning)` - Queue learning for review
   - Required fields: jobId, transcriptId, content, topic, outcome
   - Generate UUID if not provided
   - Set extractedAt to now, status to 'proposed'
   - Check for duplicate (stringSimilarity > 0.85 with existing learnings)
   - If duplicate, return { queued: false, reason: 'Similar learning exists' }
   - Find suggested profile links using getOverlapCandidates pattern:
     - If topic is 'behavioral', search stories
     - If topic is 'technical', search skills
     - If topic is 'company-specific' or 'compensation', search summaries
   - Populate suggestedProfileLinks array with matches
   - Validate with InterviewLearningSchema
   - Save to {jobId}-learnings.json
   - Return { queued: true, id, hasSuggestedLinks: boolean }

2. `reviewInterviewLearning(learningId, decision)` - Accept or reject
   - decision: { status: 'accepted' | 'rejected' }
   - Find learning by ID across all job files
   - Update status and reviewedAt
   - Save changes
   - Return { updated: true, learning } or { updated: false, reason }

3. `linkLearningToProfile(learningId, profileLink)` - Confirm profile link
   - profileLink: { entityType: 'story'|'skill'|'summary', entityId: uuid }
   - Learning must be 'accepted' status
   - Add to confirmedProfileLinks array with linkedAt timestamp
   - Remove from suggestedProfileLinks if present
   - Save changes
   - Return { linked: true, link } or { linked: false, reason }

4. `getLearningsForJob(jobId, options = {})` - Get learnings for a job
   - Options: { status: 'proposed'|'accepted'|'rejected' }
   - Load from {jobId}-learnings.json
   - Filter by status if provided
   - Return array of learnings

5. `getPendingLearnings(options = { limit: 20 })` - Get all pending across jobs
   - Scan all *-learnings.json files
   - Filter for status === 'proposed'
   - Sort by extractedAt descending (newest first)
   - Apply limit
   - Return array with jobId added to each

**Helper functions:**
- loadLearningsData(jobId) - Load or create empty { learnings: [], lastUpdated }
- saveLearningsData(jobId, data) - Atomic write pattern
- findLearning(learningId) - Search across all job files

<task type="auto">
  <name>Task 2: Create Profile Feedback Service</name>
  <files>mcp-server/src/services/profile-feedback.js</files>
  <action>
Create profile feedback service following CONTEXT.md requirements:

**Imports:**
```javascript
import { loadProfile, saveProfile } from '../data/profile-loader.js'
import { stringSimilarity } from '../data/learning-queue.js'
import { readFileSync, existsSync, readdirSync } from 'fs'
import { join, dirname } from 'path'
import { fileURLToPath } from 'url'
```

**Functions to implement:**

1. `updateProfileConfidence(learningId, outcome)` - Update item confidence
   - Find learning by ID to get confirmedProfileLinks
   - For each linked profile item:
     - Load profile
     - Find item by entityType and entityId
     - Initialize interviewUsage if not present: { totalUses: 0, workedCount: 0, needsWorkCount: 0 }
     - Increment totalUses
     - Increment workedCount if outcome === 'worked'
     - Increment needsWorkCount if outcome === 'needs-work'
     - Calculate interviewConfidence: (workedCount / totalUses) * 100
     - Save profile
   - Return { updated: true, items: [...] } with updated confidence scores

2. `getProfileUpdateSuggestions(options = {})` - Batch/aggregate suggestions
   - Options: { mode: 'batch' | 'aggregate' } (default: 'batch')
   - Load all accepted learnings with confirmedProfileLinks
   - Group by profile item (entityType:entityId)
   - For each item:
     - Load current profile item data
     - Count workedCount and needsWorkCount
     - Detect conflict: both worked AND needs-work outcomes
     - Generate recommendation:
       - hasConflict: 'Review: Mixed results in interviews'
       - workedCount > needsWorkCount: 'Working well - consider strengthening'
       - needsWorkCount > workedCount: 'Consider revising based on feedback'
   - Return suggestions array with { entityType, entityId, entityName, workedCount, needsWorkCount, recommendation, hasConflict }

3. `getInterviewPatterns(options = {})` - Detect recurring patterns
   - Options: { minOccurrences: 3, minCompanies: 2 }
   - Load all accepted learnings
   - Group by content similarity (0.7 threshold)
   - For each group with >= minOccurrences AND >= minCompanies:
     - Identify as pattern
     - Include topic, outcome distribution, example content
   - Return patterns array with { topic, occurrences, companies, outcomeDistribution, examples }

4. `detectConflicts(options = {})` - Find conflicting learnings
   - Load all accepted learnings
   - For each profile item with confirmedProfileLinks:
     - Check if any learnings have outcome 'worked' AND others have 'needs-work'
     - Flag as conflict
   - Also check for conflicts between learning content and existing profile content
     - e.g., learning says "struggled with React hooks" but profile skill says "expert"
   - Return conflicts array with { entityType, entityId, conflictType, learnings, suggestion }

**Constants:**
- PATTERN_MIN_OCCURRENCES = 3
- PATTERN_MIN_COMPANIES = 2
- CONFLICT_SIMILARITY_THRESHOLD = 0.7
  </action>
