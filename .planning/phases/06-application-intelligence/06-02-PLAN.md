<task type="auto">
  <name>Task 1: Create Enhanced Contact Schema</name>
  <files>schemas/contact.schema.js, schemas/contact.schema.test.js</files>
  <action>
Create contact.schema.js with Zod validation for enhanced contact tracking:

1. `ContactInteractionSchema` - For tracking interactions
   ```
   {
     date: z.string() (ISO date),
     type: z.enum(['email', 'linkedin', 'call', 'meeting', 'other']),
     notes: z.string().optional()
   }
   ```

2. `EnhancedConnectionSchema` - Full structured contact
   ```
   {
     id: z.string().uuid(),
     name: z.string().min(1),
     role: z.enum(['recruiter', 'hiring_manager', 'referral', 'internal_contact', 'other']),
     title: z.string().optional(),           // "Senior Technical Recruiter"
     company: z.string().optional(),          // For external recruiters
     linkedInUrl: z.string().url().optional(), // APPL-04
     email: z.string().email().optional(),
     phone: z.string().optional(),
     notes: z.string().optional(),
     isPrimary: z.boolean().default(false),
     reachedOut: z.boolean().default(false),
     lastInteraction: ContactInteractionSchema.optional(),  // APPL-04
     interactions: z.array(ContactInteractionSchema).default([]),
     createdAt: z.string(),
     updatedAt: z.string()
   }
   ```

3. `ConnectionSchema` - Union for backward compatibility
   ```
   z.union([
     z.string(),  // Legacy: "Name (notes)"
     EnhancedConnectionSchema
   ])
   ```

4. Helper functions:
   - `parseLegacyConnection(str)` - Parse "Name (notes)" into { name, notes, legacy: true }
   - `validateContact(contact)` - Validate enhanced contact, return { valid, errors, data }

Test file should cover:
- EnhancedConnectionSchema: valid full contact, minimal contact (name + role only)
- EnhancedConnectionSchema: invalid (missing name, invalid role, invalid URL)
- ContactInteractionSchema: valid interaction, invalid type
- ConnectionSchema union: accepts string, accepts object, rejects invalid
- parseLegacyConnection: "Name", "Name (notes)", edge cases
  </action>

  <done>
    - EnhancedConnectionSchema validates structured contact data
    - ContactInteractionSchema validates interaction entries
    - ConnectionSchema union maintains backward compatibility with string format
    - Helper functions for parsing and validation
  </done>

<task type="auto">
  <name>Task 2: Create Contact Management MCP Tools</name>
  <files>mcp-server/src/tools/contacts.js, mcp-server/src/tools/contacts.test.js</files>
  <action>
Create contacts.js with MCP tools following existing patterns (see updates.js):

1. `addJobContact(jobId, contactData)` - Add or update a contact (APPL-03, APPL-04)
   - Load job from loadJobsFromDashboard()
   - Validate contact using EnhancedConnectionSchema
   - Check for duplicate by name (case-insensitive) or linkedInUrl
   - If duplicate found: update existing contact, set updatedAt
   - If new: generate UUID, add to job.connections, set createdAt/updatedAt
   - Add update entry to job.updates: { date, type: 'Contact Added', notes: "Name (role)" }
   - Write back using writeJobsData()
   - Return { success, action: 'added'|'updated', contact }

2. `logContactInteraction(jobId, contactId, interaction)` - Log an interaction (APPL-04)
   - Find job and contact (by UUID)
   - Validate interaction using ContactInteractionSchema
   - Add to contact.interactions array
   - Update contact.lastInteraction
   - Set contact.reachedOut = true
   - Set contact.updatedAt
   - Write back
   - Return { success, contact, interaction }

3. `getJobContacts(jobId)` - Get all contacts for a job
   - Load job
   - Map connections, parse legacy strings using parseLegacyConnection()
   - Return:
     * jobId, title, company
     * totalContacts
     * structuredContacts: array of enhanced contacts
     * legacyContacts: array of parsed legacy entries with suggestion to convert
     * hasUncontacted: boolean (any !reachedOut)

4. `addJobUpdate(jobId, update)` - Comprehensive job update (APPL-07)
   - Accept: { note, type, connection, status, appendToNotes }
   - If note provided: add to job.updates with timestamp
   - If connection provided: call addJobContact internally
   - If status provided: validate transition, update job.status, set applied date if needed
   - If appendToNotes: append to job.notes with timestamp prefix
   - Return { success, jobId, changes: [] }

Test file should cover:
- addJobContact: new contact, duplicate detection (by name, by LinkedIn), update existing
- logContactInteraction: valid interaction, contact not found
- getJobContacts: mixed legacy and structured, empty connections
- addJobUpdate: note only, connection only, status change, combined update
- Error cases: job not found, invalid contact data, invalid status transition
- Use vi.mock for loader isolation
  </action>

    - All tools validate input and handle errors gracefully
  </done>
