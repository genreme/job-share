<task type="auto">
  <name>Task 1: Create Resume Matcher Service</name>
  <files>mcp-server/src/services/resume-matcher.js, mcp-server/src/services/resume-matcher.test.js</files>
  <action>
Create resume-matcher.js with two main functions:

1. `extractJobKeywords(description)` - Extract skills/tools/keywords from job description
   - Normalize text (lowercase, remove bullets, collapse whitespace)
   - Use regex patterns for common tech/skills categories:
     * Design tools: figma, sketch, adobe xd/photoshop/illustrator, invision
     * Frontend: react, angular, vue, typescript, javascript, html, css
     * Backend: node, python, java, sql
     * Methodologies: agile, scrum, kanban, design thinking
     * Soft skills: leadership, management, collaboration, communication
     * Domain: ux, ui, brand, creative, product design
   - Return { skills: string[], rawText: string }

2. `matchResumeToJob(profile, jobDescription)` - Compare profile against JD
   - Extract profile skills from profile.skills[].name
   - Extract experience keywords from profile.experience[].projects[].tags and descriptions
   - Compare against extracted job keywords
   - Calculate:
     * matched: keywords found in both profile and JD
     * missing: keywords in JD but not in profile (these are the GAPS - APPL-02)
     * score: (matched / totalJobKeywords) * 100, default 50 if no keywords
     * confidence: 'high' (>=5 keywords), 'medium' (2-4), 'low' (<2)
   - Return { score, matched, missing, suggestions, totalJobKeywords, confidence }

Test file should cover:
- extractJobKeywords: empty input, single skill, multiple categories, HTML entities
- matchResumeToJob: empty profile, perfect match, partial match, no match
- Partial keyword matching (skill contains substring of JD keyword or vice versa)
- Confidence level calculation
  </action>

  <done>
    - extractJobKeywords extracts skills from job descriptions
    - matchResumeToJob returns score (0-100), matched list, gaps list, and confidence
    - Tests cover edge cases and typical matching scenarios
  </done>

<task type="auto">
  <name>Task 2: Create Resume Matching MCP Tools</name>
  <files>mcp-server/src/tools/matching.js, mcp-server/src/tools/matching.test.js</files>
  <action>
Create matching.js with two MCP tools following existing tool patterns (see fit-scorer.js, updates.js):

1. `getResumeMatch({ jobId, jobDescription })` - Get match score for a single job
   - Load profile using loadProfile()
   - If jobId provided: load job from loadJobsFromDashboard(), use job.notes or job.description
   - If jobDescription provided directly: use that
   - Call matchResumeToJob(profile, description)
   - Return:
     * score: 0-100 match percentage
     * confidence: high/medium/low
     * matched: array of matched skills
     * gaps: array of missing skills (APPL-02)
     * suggestions: array of { keyword, suggestion } for gaps
     * summary: human-readable string like "75% match - 6 skills matched, 2 gaps identified"
   - Handle errors: profile load failure, job not found, no description available

2. `getMatchScoresForActiveJobs()` - Get match scores for all active jobs
   - Load profile and all jobs
   - Filter to active statuses: ['apply-now', 'maybe', 'inbox']
   - For each job, calculate match score
   - Return array sorted by resumeMatch descending:
     * { jobId, title, company, fitScore, resumeMatch, topGaps: top 3 gaps }
   - Skip jobs without description (resumeMatch: null, confidence: 'no-data')

Test file should cover:
- getResumeMatch with valid jobId
- getResumeMatch with raw jobDescription
- getResumeMatch error cases (missing profile, missing job, no description)
- getMatchScoresForActiveJobs filters correctly and sorts by score
- Mock profile-loader and loader to isolate tests

Register tools in MCP server tool registration (follow existing pattern).
