  <files>mcp-server/src/services/followup-engine.js, mcp-server/src/services/followup-engine.test.js</files>
  <action>
Create followup-engine.js with follow-up calculation and suggestion logic using date-fns:

1. Define FOLLOWUP_RULES constant (threshold days by status):
   ```
   'applied': [
     { minDays: 7, maxDays: 14, priority: 'low', suggestion: 'Consider a brief check-in if you have a contact' },
     { minDays: 14, maxDays: 21, priority: 'medium', suggestion: 'Good time to follow up - reference your application date' },
     { minDays: 21, maxDays: null, priority: 'high', suggestion: 'Follow up now - restate interest and key qualifications' }
   ],
   'inbox': [
     { minDays: 3, maxDays: 7, priority: 'low', suggestion: 'Review and decide - apply or archive' },
     { minDays: 7, maxDays: null, priority: 'medium', suggestion: 'Job may become stale - decide soon' }
   ],
   'apply-now': [
     { minDays: 2, maxDays: 5, priority: 'medium', suggestion: 'Apply soon - this was marked high priority' },
     { minDays: 5, maxDays: null, priority: 'high', suggestion: 'Apply immediately or reconsider priority' }
   ],
   'maybe': [
     { minDays: 7, maxDays: 14, priority: 'low', suggestion: 'Review again - still interested?' },
     { minDays: 14, maxDays: null, priority: 'medium', suggestion: 'Decide: apply or archive' }
   ]
   ```

2. `calculateFollowupStatus(job)` - Determine if follow-up needed (APPL-05)
   - Determine reference date: job.applied (if applied status) or job.found
   - Calculate daysElapsed using differenceInDays(now, parseISO(referenceDate))
   - Check for recent interview in job.updates (within 2 days) - special handling for thank-you
   - Match against FOLLOWUP_RULES for job.status
   - Return:
     * needsFollowup: boolean
     * priority: 'high' | 'medium' | 'low'
     * daysElapsed: number
     * referenceEvent: 'application' | 'found' | 'interview'
     * referenceDate: string
     * suggestion: string
     * reason: string (if no followup needed)

3. `generateFollowupSuggestion(job, followupStatus)` - Context-aware suggestions (APPL-06)
   - Base suggestion from rules
   - Add contact-specific suggestions:
     * If uncontacted primary contact exists: "Reach out to {name} ({role})"
     * If applied but no contacts: "Find a recruiter or hiring manager to follow up with"
     * If contact not reached in >14 days: "Re-engage with {name}"
   - Return array of { type: 'action'|'contact'|'research'|'reconnect', text, priority, contactId? }

4. `getFollowupQueue(options = { limit: 10 })` - Get prioritized queue
   - Load all jobs from loadJobsFromDashboard()
   - Filter out archived and probably-not
   - Calculate followup status for each
   - Filter to jobs where needsFollowup = true
   - Generate suggestions for each
   - Sort by priority (high > medium > low), then by daysElapsed descending
   - Limit to options.limit
   - Return array of { jobId, title, company, status, priority, daysElapsed, referenceEvent, suggestions }

Test file should cover:
- calculateFollowupStatus: applied job at 7, 14, 21+ days
- calculateFollowupStatus: inbox job at 3, 7+ days
- calculateFollowupStatus: apply-now job at 2, 5+ days
- calculateFollowupStatus: maybe job at 7, 14+ days
- calculateFollowupStatus: no followup needed (recently applied)
- calculateFollowupStatus: recent interview detection (thank-you reminder)
- generateFollowupSuggestion: with/without contacts, with uncontacted primary, stale contact
- getFollowupQueue: priority sorting, limit enforcement, status filtering
